# Implementation Plan: GitHub Releases & Sparkle Distribution

**Branch**: `006-github-releases-sparkle` | **Date**: 2026-05-27 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `/specs/006-github-releases-sparkle/spec.md`

## Summary

Automate the full release pipeline for mcp-inator: a git tag push triggers GitHub Actions to build a universal DMG, sign it with Sparkle's Ed25519 key, publish it to GitHub Releases, and update `appcast.xml` on GitHub Pages. Sparkle is already integrated in the app — the primary work is the release workflow YAML, one-time key setup, and making the repo public. Notarization is explicitly deferred (no Apple Developer account); the target audience is developers who can handle the one-time Gatekeeper bypass.

## Technical Context

**Language/Version**: Swift 6.0, YAML (GitHub Actions)

**Primary Dependencies**: Sparkle 2.x (already in project.yml), `create-dmg` (Homebrew, CI only), `peaceiris/actions-gh-pages@v4` (GitHub Actions)

**Storage**: `appcast.xml` on `gh-pages` branch (GitHub Pages)

**Testing**: Manual smoke test per quickstart.md; Sparkle signature verification

**Target Platform**: macOS 13.0+ (existing deployment target)

**Performance Goals**: Release pipeline completes end-to-end in under 10 minutes

**Constraints**: No Apple Developer account; no notarization; no code signing certificate beyond ad-hoc; Sparkle Ed25519 private key must never touch the repository

**Scale/Scope**: Single developer publishing; Sparkle auto-update for all installed users

## Phase 1: One-Time Setup (Manual Steps)

**Purpose**: Establish the Ed25519 key pair, GitHub Pages, and repo visibility. These steps are done once by the developer, not automated.

- [ ] T001 Generate Ed25519 key pair using Sparkle's `generate_keys` tool; save private key to macOS Keychain (automatic) and note the public key string
- [ ] T002 Add `SUPublicEDKey: "<public-key>"` to `project.yml` under `targets.mcp-inator.info.properties`; run `xcodegen generate` and verify the key appears in the built app's Info.plist
- [ ] T003 Export the Ed25519 private key from Keychain and store it as GitHub Actions secret named `SPARKLE_PRIVATE_KEY` in the repository settings
- [ ] T004 Create the `gh-pages` branch with an initial empty `appcast.xml` (see quickstart.md) and push to origin
- [ ] T005 Enable GitHub Pages in repository Settings → Pages → Source: `gh-pages` branch, root directory; verify `https://rayjohnson.github.io/mcp-inator/appcast.xml` is reachable
- [ ] T006 Change repository visibility to Public in GitHub Settings → General → Danger Zone

**Checkpoint**: `SUPublicEDKey` in built app Info.plist; appcast URL returns valid XML; repo is public.

## Phase 2: Release Workflow

**Purpose**: Automate the full tag → DMG → GitHub Release → appcast pipeline.

- [ ] T007 Create `.github/workflows/release.yml` with the following structure:
  - Trigger: `push: tags: ['v*']`
  - Runner: `macos-15` (consistent with existing CI)
  - Steps:
    1. `actions/checkout@v4`
    2. Select Xcode 16.3 (`sudo xcode-select -s /Applications/Xcode_16.3.app`)
    3. Install tools: `brew install xcodegen create-dmg`
    4. `xcodegen generate`
    5. Build archive: `xcodebuild archive` with `MARKETING_VERSION` set to tag (strip `v` prefix) and `CURRENT_PROJECT_VERSION` set to `$GITHUB_RUN_NUMBER`
    6. Export app from archive: `xcodebuild -exportArchive` with ad-hoc export options plist (no signing certificate required for distribution-without-notarization)
    7. Create DMG: `create-dmg` with drag-to-Applications layout, output `mcp-inator-$VERSION.dmg`
    8. Sign DMG: write `SPARKLE_PRIVATE_KEY` secret to temp file, run `sign_update --ed-key-file` → capture `edSignature` and `length`
    9. Upload DMG to GitHub Release: `gh release create $TAG --generate-notes mcp-inator-$VERSION.dmg` (or `actions/upload-release-asset`)
    10. Generate new `<item>` XML block for appcast using captured values
    11. Clone `gh-pages` branch, prepend new item to `appcast.xml`, commit and push

- [ ] T008 Create an export options plist for ad-hoc export (no Developer ID required):
  ```xml
  <!-- ExportOptions.plist -->
  <dict>
    <key>method</key><string>mac-application</string>
    <key>signingStyle</key><string>manual</string>
  </dict>
  ```
  Commit this file to the repository at `.github/ExportOptions.plist`

- [ ] T009 Verify the release workflow end-to-end by pushing a test tag (e.g., `v0.1.1-test`), confirming:
  - DMG appears on GitHub Releases
  - appcast.xml on GitHub Pages contains the new item with correct `sparkle:edSignature`
  - Sparkle in a running older build detects the update
