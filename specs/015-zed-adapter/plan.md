# Implementation Plan: Zed Editor MCP Adapter

**Branch**: `015-zed-adapter` | **Date**: 2026-06-01 | **Spec**: [spec.md](spec.md)

## Summary

Add Zed as a supported agent in mcp-inator by implementing a `ZedAdapter` conforming to `AgentAdapter`. Zed stores MCP servers under a `context_servers` key in `~/.config/zed/settings.json` using a nested command format distinct from all existing adapters. The adapter reuses `JSONAdapterHelper` infrastructure (atomic write, drift detection, JSON read) but provides its own entry parsing and serialization for the Zed-specific format.

## Technical Context

**Language/Version**: Swift 5.9, macOS 14+

**Primary Dependencies**: Foundation, XCTest (existing; no new dependencies)

**Storage**: JSON file at `~/.config/zed/settings.json`

**Testing**: XCTest — integration tests with fixture files, unit tests for isInstalled() using injected homeDirectory

**Constraints**: Must not break existing adapters; no new dependencies; must pass `make cover` threshold

**Scale/Scope**: Single new source file + one test file + one fixture file + registry entry

## Zed Config Format Mapping

Zed's `context_servers` format differs from all existing adapters:

```json
{
  "context_servers": {
    "my-server": {
      "command": {
        "path": "npx",
        "args": ["-y", "@my/mcp-server"]
      },
      "env": {
        "API_KEY": "abc123"
      }
    }
  },
  "other-zed-setting": true
}
```

Internal `MCPServerConfig` ↔ Zed mapping:
| MCPServerConfig field | Zed JSON path |
|-----------------------|---------------|
| `command`             | `command.path` |
| `args`                | `command.args` |
| `envVars`             | `env` (flat key-value object) |

## Implementation Notes

### ZedAdapter

- Conforms to `AgentAdapter`
- `homeDirectory` is injected (defaults to `NSHomeDirectory()`) for testability — same pattern as `ClaudeCodeAdapter`
- `defaultConfigPath()` → `~/.config/zed/settings.json`
- `isInstalled()` checks (any is sufficient):
  1. `~/.config/zed/settings.json` exists
  2. `~/.config/zed/` directory exists
  3. `/Applications/Zed.app` exists
- `readConfigs(from:)` → reads `context_servers` key, parses Zed entry format
- `writeConfigs(_:to:expectedExisting:)` → reuses `JSONAdapterHelper.readFullJSON`, `checkDrift`, `writeAtomic` with Zed serialization
- `removeConfig(key:from:expectedValue:)` → same infrastructure, removes from `context_servers`
- `validateServerKey(_:)` → `^[a-z0-9][a-z0-9-]*$` pattern, consistent with Cursor/Claude Desktop

### AgentRecord.swift

Add:
```swift
static let zed = AgentType(rawValue: "zed")
```

### AdapterRegistry.swift

Add `zedDef` (AgentDefinition for icon/metadata) and append `ZedAdapter()` to `all`. The `configPathRelative` in the definition is for icon lookup only — ZedAdapter uses its own `defaultConfigPath()`.

## Quickstart Test

1. Create `~/.config/zed/settings.json` with `{}` (or install Zed)
2. Launch mcp-inator — Zed should appear in the agents list
3. Add any catalog server, enable for Zed — verify `context_servers` entry written with nested `command.path`/`command.args`
4. Disable the server — verify entry removed, `otherZedSetting` (if present) unchanged
