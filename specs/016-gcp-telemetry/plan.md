# Implementation Plan: GCP Telemetry Backend

**Branch**: `016-gcp-telemetry` | **Date**: 2026-06-01 | **Spec**: [spec.md](spec.md)

## Summary

Replace the planned Cloudflare Worker (GitHub issues #39/#40) with a Go-based Cloud Run service that receives anonymous usage reports from the macOS app and stores per-server counts in Firestore. GitHub Actions deploys automatically on push via Workload Identity Federation (no stored credentials). The `refresh.py` script in `mcp-catalog` is updated to read counts from Firestore instead of a `usage.json` file. The macOS app gains the full opt-in consent and sharing UI (#40), pointed at the Cloud Run URL.

## Technical Context

**Language/Version**:
- Backend service: Go 1.22 (`net/http` + `cloud.google.com/go/firestore`)
- App: Swift 5.9 / SwiftUI (existing)
- Catalog pipeline: Python 3.11 (existing, `google-cloud-firestore` added)

**Primary Dependencies**:
- Go: `cloud.google.com/go/firestore`, `google.golang.org/api`
- GitHub Actions: `google-github-actions/auth@v2`, `google-github-actions/deploy-cloudrun@v2`
- Python: `google-cloud-firestore` (added to `mcp-catalog` requirements)

**Storage**: Firestore (native mode, `us-central1`, collection `server_usage`)

**Testing**:
- Go: `go test` (unit tests for handler logic with mock Firestore)
- Swift: XCTest (existing pattern)
- Pipeline: manual integration test per quickstart.md

**Target Platform**: Cloud Run (Linux container, Go), macOS 14+ (Swift app)

**Performance Goals**: ≤ 500ms p95 for `POST /report` (excluding cold start)

**Constraints**:
- No client IP in logs or storage (FR-005)
- Static bearer token for public endpoint auth (Moov org policy blocks `allUsers` IAM)
- No long-lived GCP credentials in GitHub — Workload Identity Federation throughout

**Scale/Scope**: Low traffic (hundreds of app installs → occasional reports). Scale-to-zero is fine.

## GCP Infrastructure (One-Time Setup)

Documented in `scripts/setup-gcp.sh`. Runnable in order:

```bash
PROJECT=ray-johnson-mcp-inator
REGION=us-central1
GITHUB_REPO=rayjohnson/mcp-inator
CATALOG_REPO=rayjohnson/mcp-catalog

# 1. Enable APIs
gcloud services enable \
  run.googleapis.com \
  firestore.googleapis.com \
  artifactregistry.googleapis.com \
  iam.googleapis.com \
  iamcredentials.googleapis.com \
  --project=$PROJECT

# 2. Firestore (native mode)
gcloud firestore databases create \
  --location=$REGION --project=$PROJECT

# 3. Artifact Registry
gcloud artifacts repositories create mcp-inator \
  --repository-format=docker \
  --location=$REGION \
  --project=$PROJECT

# 4. Workload Identity Pool + Provider
gcloud iam workload-identity-pools create github-pool \
  --location=global --project=$PROJECT

gcloud iam workload-identity-pools providers create-oidc github-provider \
  --location=global \
  --workload-identity-pool=github-pool \
  --issuer-uri=https://token.actions.githubusercontent.com \
  --attribute-mapping="google.subject=assertion.sub,attribute.repository=assertion.repository" \
  --project=$PROJECT

# 5. Deploy service account (mcp-inator repo)
gcloud iam service-accounts create github-actions-deployer \
  --project=$PROJECT

gcloud projects add-iam-policy-binding $PROJECT \
  --member="serviceAccount:github-actions-deployer@$PROJECT.iam.gserviceaccount.com" \
  --role="roles/run.developer"

gcloud projects add-iam-policy-binding $PROJECT \
  --member="serviceAccount:github-actions-deployer@$PROJECT.iam.gserviceaccount.com" \
  --role="roles/artifactregistry.writer"

PROJECT_NUMBER=$(gcloud projects describe $PROJECT --format='value(projectNumber)')

gcloud iam service-accounts add-iam-policy-binding \
  github-actions-deployer@$PROJECT.iam.gserviceaccount.com \
  --member="principalSet://iam.googleapis.com/projects/$PROJECT_NUMBER/locations/global/workloadIdentityPools/github-pool/attribute.repository/$GITHUB_REPO" \
  --role="roles/iam.workloadIdentityUser" \
  --project=$PROJECT

# 6. Catalog read-only service account (mcp-catalog repo)
gcloud iam service-accounts create github-catalog-reader \
  --project=$PROJECT

gcloud projects add-iam-policy-binding $PROJECT \
  --member="serviceAccount:github-catalog-reader@$PROJECT.iam.gserviceaccount.com" \
  --role="roles/datastore.viewer"

gcloud iam service-accounts add-iam-policy-binding \
  github-catalog-reader@$PROJECT.iam.gserviceaccount.com \
  --member="principalSet://iam.googleapis.com/projects/$PROJECT_NUMBER/locations/global/workloadIdentityPools/github-pool/attribute.repository/$CATALOG_REPO" \
  --role="roles/iam.workloadIdentityUser" \
  --project=$PROJECT

# 7. Generate bearer token and store in Secret Manager
# (Generate a random token, then store it)
BEARER_TOKEN=$(openssl rand -hex 32)
echo "TELEMETRY_BEARER_TOKEN=$BEARER_TOKEN"  # Save this — add to GitHub Actions secrets

echo "Setup complete. Add to GitHub Actions secrets:"
echo "  TELEMETRY_BEARER_TOKEN=$BEARER_TOKEN"
echo ""
echo "Add to GitHub Actions variables (not secrets):"
echo "  GCP_PROJECT=$PROJECT"
echo "  GCP_REGION=$REGION"
echo "  GCP_WIF_PROVIDER=projects/$PROJECT_NUMBER/locations/global/workloadIdentityPools/github-pool/providers/github-provider"
echo "  GCP_DEPLOY_SA=github-actions-deployer@$PROJECT.iam.gserviceaccount.com"
echo "  GCP_CATALOG_SA=github-catalog-reader@$PROJECT.iam.gserviceaccount.com"
```

## Firestore Data Model

Collection `server_usage`, one document per server key:
```
server_usage/{serverKey}
  count:       int64      (FieldValue.increment — atomic)
  firstSeenAt: timestamp
  lastSeenAt:  timestamp
```

## App-Side Sanitization Rules (UsageSharingService)

- `command`: basename only (no path)
- `args`: each segment is included; filesystem paths are redacted to `<path>` (any segment starting with `/` or `~`)
- `envVars`: key names only, values never sent
- Private servers (`isPrivate = true`): excluded from payload entirely
- User-excluded servers (per-server toggle on review screen): excluded from payload

## Zed Adapter Note

The `ZedAdapter` (PR #53, merged) is already in the codebase. `UsageSharingService` will automatically include Zed-managed servers in reports when the user opts in, following the same sanitization rules.
